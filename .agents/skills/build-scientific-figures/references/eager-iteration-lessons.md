# EAGER Figure 1: lessons from repeated author review

Use this case when a technically correct figure remains visually weak, small illustrations are
unclear, or local polishing repeatedly fails to satisfy the author. The notes summarize the
author's successive reviews and the accepted manuscript integration. They are design observations,
not a benchmark of aesthetic quality or a universal layout template.

No private manuscript, trace, simulation image, generated candidate, or third-party reference
figure is bundled here. The project-specific facts below explain design decisions; verify the
new project's own evidence before adapting any scientific relationship.

## What changed the design decisions

| Unsuccessful approach | Diagnosis | Useful adjustment | Boundary |
| --- | --- | --- | --- |
| A tidy system pipeline carrying most of the visual weight | It named modules but hid the central contrast | Make the schema-valid command, execution limit, feedback, and revised command the main mechanism scene | A real photo or plot can be the hero in a different paper |
| Repeated cards, followed by removing almost all framing | Neither treatment created useful hierarchy | Use aligned outer groups with shared titles; reserve local boundaries for genuinely different content | Borders are a grouping tool, not a fixed aesthetic rule |
| A right column of tiny icons and long names | It read as a settings menu; whitespace separated rows without explaining them | Give assessments explanatory area, then clarify records, processing, and results with local links | Parallel assessment plates were an intermediate design, not the prescribed endpoint |
| Magnifier behind an unspecified object | The picture said “inspect” without showing what was inspected | Show a specific event/field relationship, or show the actual script processing records | Do not add a magnifier merely because the label says analysis |
| Anonymous record strips, blank templates, and distance-only boxes | Repeated silhouettes and unexplained slots were interchangeable | Use field names and explicit correspondences; distinguish source events from evaluation outputs | Empty cells can be valid when their missing/placeholder meaning is explicit |
| More elaborate cute generated icons | Binding rings, thick outlines, and decorative detail dominated the small footprint | Establish a thin-line, pale-fill family and select by actual paper-size meaning | This was the author's preferred style, not a universal publication requirement |
| Removing Analysis / required as if it were only typography | The removal could obscure who computes results and what reproduction requires | Show a script-page/gear between Trace and Results; retain offline script and required-analysis meaning in the caption | The friendly thinking gear does not introduce an LLM evaluator |
| Declaring success from editability and no overflow | Technical correctness did not resolve author-visible design problems | Track the specific defect and inspect fresh local and whole-figure renders | No self-score establishes top-conference visual quality |
| Accepting a sharp slide PNG as proof of export quality | Office PDF export had reduced embedded image dimensions | Inspect the PDF itself; restore exact original pixels only through a verified export-specific mapping | Do not promote fixed PDF object identifiers into a universal tool |

## Scientific and scale constraints that shaped the figure

The example distinguished a schema-valid 100 m command from an executor's 5 m segment limit.
Revised waypoints through 50 m represented a plan, not measured travel or goal arrival. The figure
kept interface validity and repair outcome separate, and identified controlled simulation frames
as illustrative witnesses rather than aggregate performance evidence.

The source canvas was 183 x 78 mm, but the manuscript inserted it at 160 mm width. Source labels
therefore became smaller on paper. Four approved field micro-labels remained a stated limitation;
their acceptance in this case is not a recommendation to use tiny text elsewhere. Face details in
the script gear were secondary to its code-page and gear silhouette.

## How to apply the lesson without replaying every round

1. State the main contrast and the role of each region before choosing frames or illustrations.
2. For an unclear component, use the actor/object/operation brief in
   [academic-2d-illustrations.md](academic-2d-illustrations.md); do not start by embellishing it.
3. Preserve approved regions and test the proposed local change with its real labels at paper size.
4. Record the observation, cause, change, new-render evidence, and remaining limitation as described
   in [story-first-hero.md](story-first-hero.md).
5. After acceptance and an integration request, inspect the compiled manuscript using
   [pptx-figure-hardening.md](pptx-figure-hardening.md). Approval of a standalone source does not
   establish correct PDF export or paper-scale readability.

The accepted solution was specific to this author and figure. Reuse the diagnostic method and
scientific distinctions, not its three-column widths, icon choices, candidate counts, or colors.
